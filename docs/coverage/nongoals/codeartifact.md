- All 48 operations of the API (`aws-sdk-go-v2/service/codeartifact` v1.45.0) are served. What is not emulated is the package-manager side: there is no npm, pip, Maven, NuGet, RubyGems, Cargo, Swift or generic registry protocol. `GetRepositoryEndpoint` and `aws codeartifact login` work and report the URL AWS reports (`https://<domain>-<owner>.d.codeartifact.<region>.amazonaws.com/<format>/<repository>/`), but nothing serves that host, so `npm install` and `pip install` against it do not reach the emulator. The `dualstack` and `ipv4` endpoint types return the same host.
- Only generic packages can be created through the API, which is also true of real AWS (`PublishPackageVersion` is generic-only). `PutPackageOriginConfiguration` creates an empty package record of any format. Packages of other formats never appear on their own.
- An external connection is stored (its name, the package format it serves, status `Available`) but nothing is fetched from the public registry, so no version has the `EXTERNAL` origin type and `ListPackageVersions` with `originType` `EXTERNAL` or `UNKNOWN` is always empty. Retaining versions from upstream repositories happens only through `CopyPackageVersions` with `includeFromUpstream`.
- Generic package versions carry no metadata the emulator can read, so `GetPackageVersionReadme` returns an empty readme, `ListPackageVersionDependencies` an empty list, and `DescribePackageVersion` has no `summary`, `homePage`, `sourceCodeRepository` or `licenses`.
- Asset bytes are kept in memory. The limit per asset is 128 MiB (AWS: 5 GiB, adjustable) and a package version holds at most 350 assets, as in AWS; a larger asset answers `ServiceQuotaExceededException`. Assets are stored once per domain, so `assetSizeBytes` sums the distinct SHA-256 digests in the domain. A snapshot taken without assets keeps the name, size and hashes of every asset but not its bytes: downloading one afterwards answers `ResourceNotFoundException`. `--persist` always keeps the bytes.
- The request-rate quotas (publish 10/s, copy 5/s, token 40/s and the rest) and `ThrottlingException` are not modelled. `AccessDeniedException` comes only from `--enforce-auth` identity policies: domain and repository permissions policies are validated (a JSON document with a `Statement`, at most 7168 bytes) and stored with an optimistic-lock revision, but never evaluated, and cross-account access is not modelled. A domain and its repositories always belong to the emulator's single account, so the domain owner and the repository administrator are the same account and a package version event is delivered once.
- The `encryptionKey` of a domain is stored and returned but not checked against KMS and not used: assets are not encrypted. The `s3BucketArn` is a synthesized name; no bucket exists.
- Authorization tokens are opaque random strings valid for the requested duration (0 means the 12-hour default; AWS ties 0 to the caller's role session). Nothing consumes them: no registry checks a token.
- Only the `CodeArtifact Package Version State Change` EventBridge event is emitted: on publish, adding an asset, a status change, copy, dispose, delete versions and delete package (one event per version), with the documented detail and a per-package `sequenceNumber`. The issue asks for a repository state-change event, but AWS documents no payload for it (its EventBridge reference names it "Goshawk Repository State Change" and its CodeArtifact guide lists only the package version event), so none is emitted. Deleting a repository removes its packages without per-version events (a domain cannot be deleted while it has repositories). Ingestion events do not exist because nothing is ingested.
- The AWS reference does not state these behaviours; they were chosen conservatively and are unconfirmed against the live service: publishing a package that its package or group origin controls block, or a version that already exists in an upstream, answers `ConflictException`; a SHA-256 header that does not match the content answers `ValidationException`; adding an asset to a Published version answers `ConflictException`; downloading from an Archived version answers `ConflictException`; a name that is not one of the ten supported external connections, and an upstream that does not exist, answer `ResourceNotFoundException`; a repository that is another repository's upstream cannot be deleted (`ConflictException`); a repository holds upstreams or an external connection, not both; a package whose last version is deleted disappears unless its origin controls were set explicitly; a status update does not change a version's revision; package group errors carry a `resourceId` but no `resourceType`, because the API's `ResourceType` values do not include a package group; `DeleteDomain` answers `ValidationException` for a domain that does not exist, because the API does not model `ResourceNotFoundException` for it; a new domain has no default `/*` package group.
- A version's `revision` is a 32-character digest of its assets: it changes when an asset is added, removed or replaced, and stays the same across reads and status changes. A copy keeps the source revision.
- Package group patterns follow the grammar and word-boundary matching in the user guide. Matching a package to a group is exact (strong) or case, dash, dot and underscore tolerant (weak); the confusable-character normalization is not performed, and Python, NuGet and Swift names are not normalized before matching. A new group's three restrictions start as `INHERIT`, which resolves to `ALLOW` when no parent sets one. A weak match blocks publishing. Deleting a group re-parents its children and deleting a repository drops it from the allowed repository lists.
- Package origin controls default to publish `ALLOW` and upstream `BLOCK` for a package whose first version is published directly, or `ALLOW`/`ALLOW` when its group restricts anything. Origin controls limit publishing; upstream restrictions are stored and listed but only block a publish through the upstream-presence rule, because no ingestion exists.
- List operations take `maxResults` (1 to 1000, default 100) and `nextToken`, an opaque offset over results in a fixed order (names, or newest-published first for versions), so it is only stable while the list does not change between pages. A token the emulator did not issue is a `ValidationException`.
- `ListAssociatedPackages` and package group matching only see packages that exist in a repository (plus the packages `preview` evaluates for a group that does not exist yet); `GetAssociatedPackageGroup` works for coordinates that exist nowhere.
