- Resource statuses (`CREATE_IN_PROGRESS` to `ACTIVE` for services, target groups, the three association kinds, resource gateways and resource configurations) and target health (`INITIAL` to `HEALTHY`) settle on the mock's clock only when async settling is on (`--async-settle` / `config.WithAsyncSettle`); otherwise they are final immediately. Settle windows are in memory and are not part of snapshots, so a restored resource reports its final state. Only the create-time transition is modeled: there is no `UPDATE_IN_PROGRESS` or `DELETE_IN_PROGRESS`, and no health checking against real targets.
- A target group's `serviceArns` is derived at read time from the listener default actions and rules that forward to it. Deleting a target group while any of them still forwards to it is rejected with `ConflictException`. A rule or listener action that names a target group that does not exist is still accepted.
- Every listener has a synthesized default rule (`isDefault` true, name `default`, no priority) built from the listener's default action. `ListRules` and `GetRule` return it. `UpdateRule`, `BatchUpdateRule` and `DeleteRule` on it are rejected with `ValidationException`, as the API reference says ("You can't modify a default listener rule. To modify a default listener rule, use `UpdateListener`"), so the default action changes only through `UpdateListener`. Its id is derived from the listener id. Whether real VPC Lattice reports a priority for the default rule is unconfirmed.
- Rule priority must be 1 to 2000 (the documented range in the CreateRule and UpdateRule API reference) and unique per listener (`ConflictException` on a duplicate, also per item in `BatchUpdateRule`). Service names and service network names are unique per account and region (`ConflictException`). Only the `(service network, service)` association pair is checked for duplicates; duplicate VPC and resource associations, duplicate target group names and duplicate listener ports are still accepted.
- Creating a service network VPC association checks the VPC exists in the emulated VPC service and answers `ResourceNotFoundException` when it does not (the exception real AWS uses is unconfirmed). A standalone `vpclattice.Mock` without the VPC service wired accepts any VPC id. Access log subscriptions check that the resource (service network, service or resource configuration) exists, not the destination.
- `authType` is validated against `NONE` and `AWS_IAM`, target group `type` against `IP`, `LAMBDA`, `INSTANCE` and `ALB`, listener `protocol` against `HTTP`, `HTTPS` and `TLS_PASSTHROUGH` with port 1 to 65535 (an omitted port defaults to 80 for HTTP and 443 for HTTPS; `TLS_PASSTHROUGH` has no documented default, so it needs an explicit port and is rejected with `ValidationException` without one, which is unconfirmed against the live service). Target group config protocol, resource name format and the other field-level rules are not validated. `PutAuthPolicy` requires a JSON object; the newline and blank-line rule in the API reference is not enforced, and `PutResourcePolicy` is not validated.
- List operations take `maxResults` (1 to 100, default 100) and `nextToken`. The token is an opaque offset over the sorted result, so it is only stable while the list does not change between pages.
- VPC Lattice calls are recorded as CloudTrail management events (event source `vpc-lattice.amazonaws.com`, name from the HTTP method and path, read-only by verb prefix) with the same minimal event body the other services get.
- Target health reports `INITIAL`, `HEALTHY` and `DRAINING` only. Real VPC Lattice also reports `UNUSED` for targets in a group that no listener or rule forwards to, plus `UNAVAILABLE` and `UNHEALTHY` from health checks; none of these are modeled, and no health check runs against a real target.
