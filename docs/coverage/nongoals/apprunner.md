- Services do not run your code or image: there is no data plane. `ServiceUrl` and VPC ingress `DomainName` are synthesized and not reachable, and request/latency/HTTP-status metrics are never emitted (the CloudWatch mock only gets `ActiveInstances`, 0 while a service is paused and 1 while it runs). Log groups `/aws/apprunner/<name>/<id>/service` and `/application` are created but receive no events.
- Custom domains stop at `PENDING_CERTIFICATE_DNS_VALIDATION`: the emulator cannot validate DNS, so they never reach `ACTIVE`. Certificate validation records and the DNS target are synthesized.
- VPC connector subnet and security group checks, and the VPC ingress connection endpoint, only consult the networking mock when the AppRunner mock is wired to one (the default `NewAWS` provider does this); a standalone `apprunner.Mock` accepts any ids. VPC ingress `VpcId` and `VpcEndpointId` are stored as given, not looked up.
- Services, ingress connections and custom domains are created ready at once so IaC waiters complete; with `--async-settle` they report `OPERATION_IN_PROGRESS` / `PENDING_CREATION` first for a short window and mutating calls then raise `InvalidStateException`. A service never ends `CREATE_FAILED`.
- Source code builds are not run: a code repository service never reads the repository, and `ConnectionStatus` of a connection is `AVAILABLE` without the OAuth handshake.
- Defaults the AWS docs do not state exactly are the emulator's choice: instance configuration 1 vCPU / 2 GB, health check TCP with interval 5, timeout 2, healthy threshold 1, unhealthy threshold 5, path `/`. Error message text is descriptive; the exception types are the documented ones.
- Lists return everything when `MaxResults` is not given (real App Runner pages at its own default); `MaxResults` is validated to 1-100.
