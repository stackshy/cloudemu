- Nothing runs: training, processing, transform, tuning, AutoML, labeling and compilation jobs, pipeline executions and monitoring executions are records that move through the real status values, never containers. `InvokeEndpoint` echoes the request body, and an endpoint's container is never started or health-checked.
- Streaming and batch runtime calls that are not served: `InvokeEndpointWithResponseStream`, and the feature-store runtime `BatchGetRecord`.
- Model Monitor executions are generated on a schedule's cron cadence and are always `Completed` (a seeded status can be set from Go); monitoring alerts cannot be created through the API (AWS creates them from Model Dashboard violations), so `ListMonitoringAlerts` is empty when the emulator runs as a server; the seeding hook is a test seam and is not part of the production surface, and the nested job-definition configuration is stored and echoed verbatim without being validated.
- `Search` covers the resource types the emulator stores (training jobs, tuning jobs, endpoints, models, model packages and groups, pipelines and their executions, experiments, trials, trial components, feature groups, projects); a valid resource type it does not store (images and image versions, feature metadata, model cards, pipeline versions, `Job`) returns an empty result rather than an error. `GetSearchSuggestions` suggests the `Tags.`, `HyperParameters.` and `Parameters.` property names the stored resources carry.
- Metrics carry nominal constant values (the real service publishes measured latency and utilization): per-job host utilization is published when a job is created and is skipped under `--async-settle`, and `Invocation5XXErrors` and `InvocationModelErrors` appear only when a model failure is seeded from a Go test or the caller names a variant the endpoint lacks (4XX); a successful invocation does not publish a zero datapoint, so an error-rate average over successes alone reads as 1 instead of 0.
- EventBridge events are published for training, processing, transform and tuning jobs, endpoints, model packages and pipeline executions. There are no Step Status Change, Model, Feature Group, Image, HyperPod or Endpoint Deployment events, and under `--async-settle` the first state of a change is published at call time and the settled state (IN_SERVICE, Completed, Stopped, Failed) once, the first time the resource is read after it settles, because the mock has no scheduler; state restored from a persisted snapshot can publish its settled state again on its first read. The endpoint status in the event detail follows the upper-snake form in the AWS example (`IN_SERVICE`), which AWS does not document further.
- Workforces: one workforce per account, `Active` immediately, and no sign-in portal or labeling UI is served; `ListSubscribedWorkteams` is always empty (no Marketplace vendors).
- Studio custom images are registered by reference: the base image is never pulled or built, so a version is `CREATED` at once and `ContainerImage` is the base image.
- Projects are provisioned by reference: the Service Catalog product is never launched, so a project is `CreateCompleted` at once with no provisioned products or pipelines behind it.
- Limits and message texts that AWS documents only as "see Service Quotas" (the 500-project and 25-workteam caps) are the emulator's choice; the exception names are the documented ones.
- Target-group-style list defaults follow the documented ones (`SortOrder` Descending for ListEndpoints, ListModels, ListEndpointConfigs and ListTransformJobs; `SortBy` Name for ListCodeRepositories and ListNotebookInstances). A filter on a field an operation does not have is a `ValidationException`, never an empty result.
- Known fidelity gaps left for follow-up: error message wording differs from AWS (AWS quotes ARNs and uses `Cannot create already existing ...`); ARNs keep the caller's name casing where AWS lowercases the name segment; lineage ARNs use a shorter id than AWS; `DeployedImages.ResolvedImage` is a copy of the image tag, not a digest; notebook instances skip `Pending` under `--async-settle`; the 1 MiB control-plane body cap rejects a maximum-size `PipelineDefinition` once JSON-escaped; and event payloads carry the tags the resource had at creation.
