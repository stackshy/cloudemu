- Aliases, versions, knowledge bases and data sources are created directly in their final state (`PREPARED`, `ACTIVE`, `AVAILABLE`). Agents and flows start `NOT_PREPARED` / `NotPrepared`; PrepareAgent and PrepareFlow prepare them at once, and any change to the draft makes it unprepared again. Ingestion jobs complete at once; with `--async-settle` they report `IN_PROGRESS` for two seconds first, which is the only window in which `StopIngestionJob` succeeds. A stop of a finished job is a `ConflictException`.
- `PrepareAgent` does not cut a version, as in AWS. A version is cut when `CreateAgentAlias` or `UpdateAgentAlias` is called without `routingConfiguration`; it copies DRAFT with its action groups, knowledge-base associations and collaborators. Agent and flow versions report `PREPARED` / `Prepared` whatever DRAFT's status was.
- Every agent has the `TSTALIASID` test alias routed to DRAFT; it is listed and readable and can't be updated or deleted. Flows have no synthesized test alias.
- `promptOverrideConfiguration` returns what the caller set. AWS's default prompt templates are not reproduced, so an agent created without overrides reports an empty `promptConfigurations` list.
- `guardrailConfiguration`, `memoryConfiguration`, `customOrchestration`, action-group executors and schemas, flow definitions and document content are stored and returned as sent; nothing runs them. Knowledge-base documents are tracked by identifier and reported `INDEXED`; their text is kept whole (no chunking or embedding) for the agent runtime's word-overlap search. An ingestion job over an S3 data source syncs the bucket from cloudemu S3: text objects (`.txt`, `.md`, `.html`, `.csv`, `.json` or a `text/*` content type) under the inclusion prefixes are indexed with their `<key>.metadata.json` attributes, changed and removed objects are re-indexed or dropped, and other formats count as failed. The sync runs when the job starts (under `--async-settle` the documents are searchable while the job still reports `IN_PROGRESS`); a bucket that can't be listed makes the job `FAILED` with a `failureReasons` entry and leaves the index unchanged. Under `--enforce-auth` the job reads S3 as the knowledge base's service role: a role that does not exist or lacks `s3:ListBucket` fails the job, and objects it lacks `s3:GetObject` on count as failed. Other data-source types (web, Confluence, SharePoint, Salesforce) are not crawled; their ingestion statistics count the documents ingested into them directly.
- `ValidateFlowDefinition` checks structure only: a missing Input or Output node, connections to unknown nodes, duplicate connections, and nodes not reachable from an Input node. Node configurations, expressions, data types, conditions and loops are not checked, and the messages are the emulator's own wording.
- `skipResourceInUseCheck` matters only for `DeleteAgentVersion` and `DeleteFlowVersion`: a version an alias routes to is in use. Deleting an agent, flow, prompt or knowledge base cascades to its children without an in-use check, and `DeleteAgentActionGroup` does not require the action group to be disabled.
- Deleting a knowledge base leaves agent associations to it in place, and deleting an agent or alias leaves other agents' collaborators that point at that alias in place.
- Document `metadata` (inline attributes, or an `S3_LOCATION` metadata file read from cloudemu S3) is stored and used by the runtime's retrieval filters, but not returned by GetKnowledgeBaseDocuments or ListKnowledgeBaseDocuments.
- Where AWS does not document the exact message (for example a missing VECTOR `storageConfiguration`, a bad `nextToken`, an alias name in use, a version in use, a non-supervisor agent given a collaborator), the emulator returns the documented exception with its own wording.
- `clientToken` is validated but does not make a create idempotent.
